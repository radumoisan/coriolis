    Build and Deploy Instructions¶

    Prepare local repo¶

    Clone conductor repository¶

    git clone git@github.com:virtomat/ci-test-repo.git virt-ci-test-repo
    Initial directory structure should look like this: (expand to see) 
    radu@ThinkPad-L380$ tree -L 2
.

│    └── test.md
├── helm

    Docker Image¶

    You can build the image with (local usage): 

    docker build . -t testapp

    Note

    As this repo is integrated on the CI pipeline, there is no need to push the image
    Building the image locally is for testing purposes when (for some reason) the build fails.

    Helm Chart¶

    Prerequisites¶

    Create regcred docker registry secret. This has to have Read permission over virtomat project (to pull cixpress images) and Read/Write permissions over target project. 

    kubectl -n cixpress create secret docker-registry regcred \
           --docker-server=cr.virtomat.io \
           --docker-username='robot-virtomat+cixpress' \
           --docker-password='07NESZAGTyubvOW2aIOTHMBVlxuTGZ3o'

    Installation (Dev Cluster)¶

    From source code repository(for reference only): 

    helm install testapp ./helm
    From published helm chart: 
    helm install testapp oci://cr.virtomat.io/virtomat/cixpress/helm/testapp

    Note

    As this chart is integrated on the CD pipeline, there is no need to install it manually. CD is managed with ArgoCD

    Installation (Local Dev Cluster)¶

    helm -n cixpress install conductor ./helm \
          --set logging=DEBUG \
          --set ingress.enableTLS=false \
          --set persistence.mount_dev_dir=true \
          --set dev_dir_path=/home/radu/Dev/virt-ci-test-repo

    helm -n cixpress install conductor oci://cr.virtomat.io/virtomat/cixpress/helm/conductor \
          --set logging=DEBUG \
          --set ingress.enableTLS=false \
          --set persistence.mount_dev_dir=true \
          --set dev_dir_path=/home/radu/Dev/virt-ci-test-repo

    Mounting local workdir inside the runtime container

    Mounting local workdir inside the runtime container allows live modifications (in your IDE of choice) and reloads of the application runtime without any workarounds. This requires a working local microk8s cluster

    Proxy-forward webhook calls from github

    Proxy-forward webhook calls from github to local environment (https://www.ultrahook.com/) 

    ultrahook conductor http://ci.dev.virtomat.io/conductor/start-build-pipeline

    Verify the installation¶
